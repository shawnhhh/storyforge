# 第二阶段：备份、恢复与小说导出

“备份与恢复”显示上次备份时间、历史、大小、创建时间、schema 版本和 SHA-256，提供手动备份、完整性检查与两步恢复。小说右上角可选择 Markdown / TXT / JSON 并下载。

## 数据位置与安全机制

现有数据库位置不变：默认 `data/storyforge.sqlite`，由 `STORYFORGE_DATA_DIR` 配置。没有新增或修改迁移脚本，不重置现有数据。备份默认保存在 Mac 用户目录的 `~/Library/Application Support/StoryForge/Backups`，独立于源码；目录权限 0700，快照及元数据 0600。`STORYFORGE_BACKUP_DIR` 可设置为项目外的绝对路径，请写完整路径，不要填 `~`。备份设置保存在该目录的 `settings.json`。

备份使用 Node 24 `node:sqlite.backup()`，即 SQLite 官方 online backup API，包含 WAL 中已提交但尚未 checkpoint 的内容。完成后将快照设为独立的 DELETE journal 数据库，通过文件头、`integrity_check`、外键、完整 schema 签名、迁移版本和 Tiptap 正文检查，计算大小、SHA-256 后发布历史。未完成的 `.pending` 文件不会被列为可恢复备份。检查会拒绝未经校验的 WAL/SHM/journal 附属文件、路径穿越、符号链接及硬链接。

恢复只接受历史备份 ID，不接受任意文件路径。首次确认替换风险后进行验证，第二步需输入“替换当前全部数据”；确认令牌有效期 5 分钟，仅使用一次。服务先生成目标备份的私有校验快照，为当前数据库创建安全备份，再使用现有连接，在 `BEGIN IMMEDIATE` 事务中恢复 schema v2 的全部应用表：小说、章节、人物、世界观、人物关系、设定关联和迁移记录。不替换正在使用的数据库文件，不删除活动数据库 WAL/SHM，不重建连接。恢复期间暂停 API 写入；失败由事务回滚，进程意外退出时 SQLite 通过事务/WAL 保护原数据。未知 schema、较新版本或不兼容正文均拒绝恢复。

第三阶段继续兼容第二阶段 v1 历史备份：先校验原始 v1 结构与内容，仅迁移私有临时副本到 v2，再执行事务恢复。原备份文件及 SHA-256 保持不变。v1 备份没有人物与世界观资料，恢复后这些资料库为空；恢复前当前完整资料会保存在 v2 安全备份中。界面确认提示会说明这一行为。

恢复成功或服务重启后，旧浏览器会话写入返回 409，编辑器保留草稿。请先导出未保存草稿，再刷新**整个页面**；“刷新本地数据”不会更换会话。恢复成功界面提供“重新加载工作台”。其他 Safari/Chrome 窗口也须刷新。本地服务只监听 127.0.0.1，检查 Host、浏览器 Origin 和写入会话，不开放跨域。

同一数据目录只允许一个 StoryForge 服务运行，通过独立的 SQLite 服务锁防止多个服务绕过恢复后的会话保护。锁数据库与作品数据库分离，操作系统会在异常退出后释放锁；数据库文件不会因此删除。SQLite 自身事务锁继续保护其他只读连接。

## 自动备份的触发条件

自动备份默认开启。服务成功开始监听后立即检查，以后每 60 秒检查。没有成功自动备份，或距上次成功自动备份满 24 小时，则创建一次。手动备份不会改变自动备份计时。失败在界面显示错误，后续检查重试。

**服务关闭时不运行自动备份。**没有安装 launchd、cron 或后台常驻任务。Mac 休眠期间不触发，唤醒或重新启动服务后在下一次检查补做一次，不补做多个历史日期。

默认保留最近 14 份自动备份，可改为 1–365 份或关闭；成功自动备份后清理超额自动备份。减少数量需要确认。手动备份与恢复前安全备份始终保留，不自动清理。

## 导出内容

导出读取已保存内容，按 `position, id` 排序。未保存时按钮禁用。Markdown/TXT 从 Tiptap JSON 树转换，保留段落、标题、列表、嵌套列表、引用、换行与代码块；Markdown 还保留可表达的行内格式并转义特殊字符。JSON 包含格式版本、导出时间、小说元数据、章节顺序、标题、完整正文、正文 schema 和并发版本。单本小说导出格式保持第二阶段契约，不包含人物或世界观；保留全部资料请使用数据库备份。

文件使用 UTF-8，保留中文和 emoji 文件名，非法路径字符替换为下划线。通过浏览器下载，服务不写入用户选择的导出目录。

## Mac Safari 验收步骤

1. Node 24 下运行 `npm run dev:all`，Safari 打开 `http://127.0.0.1:5173`。Safari“设置 → 通用 → 文件下载位置”选择“每次下载时询问”，便可自行选择导出保存位置。
2. 用专门验收的小说输入中文、emoji、段落、标题和列表；添加多个章节并调整顺序，等待“已保存”。依次导出三种格式，检查下载文件名、中文、格式和章节顺序。
3. “备份与恢复 → 手动备份”，等待成功；核对时间、大小和 SHA-256，点击“检查完整性”，应显示通过。用 Finder“前往文件夹”打开上述备份目录，确认位于项目外。
4. 返回写作，修改测试正文并保存。选择修改前的备份，先取消首次恢复确认，数据应保持不变。再次恢复，接受首次提示，在对话框输入“替换当前全部数据”并确认。**恢复会替换全部小说，建议在独立测试目录验收；操作前保存其他窗口，并导出草稿。**
5. 等待“恢复成功”，确认出现“恢复前安全备份”；点击“重新加载工作台”，检查小说、章节顺序与正文回到备份时的状态。需要返回恢复前状态时，可恢复刚生成的安全备份。旧窗口写入应显示冲突并保留草稿，刷新整个页面后才能继续写作。
6. 验证自动备份：无自动备份的首次启动立即创建；同一天重启不重复创建；服务持续运行满 24 小时后，下一分钟检查创建新备份。服务关闭后不产生新备份，重新启动后补做一次。修改保留数量并重启，确认设置持久化。

独立验收可在单独终端运行：

```sh
export STORYFORGE_DATA_DIR="$(mktemp -d)"
export STORYFORGE_BACKUP_DIR="$(mktemp -d)"
npm run dev:all
```

这两个目录只用于验收，不读取已有作品。真实服务占用端口时，先停止它或另设 `SERVER_PORT`；不要覆盖现有 `.env`。

## 接口与测试

- `GET /api/novels/:id/export?format=markdown|txt|json`
- `GET / POST /api/backups`：历史 / 手动创建
- `PUT /api/backups/settings`：enabled + retention
- `POST /api/backups/:id/verify`：检查
- `POST /api/backups/:id/prepare-restore`：验证并返回确认令牌
- `POST /api/backups/:id/restore`：token + confirmation（“替换当前全部数据”）

所有写入须携带读取响应中的 `X-StoryForge-Generation`，恢复/重启后失效。备份或恢复期间写入返回 423，会话不一致返回 409；正文并发版本保护继续生效。

自动化测试覆盖 WAL、故障回滚、安全备份、校验和版本拒绝、路径/链接拒绝、会话失效、自动备份计时/保留、中文富文本和排序、浏览器下载及两步恢复。所有测试数据库及备份目录均为独立临时目录。`npm run typecheck`、`npm run lint`、`npm run build`、`npm test`、`npm run test:e2e` 是完整检查命令。Safari 实际下载和恢复仍需在 Mac 按上述步骤验收。
