## 本轮实现

人物生成结果必须包含既有资料结构的分类、标签，以及别名、性别、年龄、身份、外貌、性格、背景经历、人物目标和角色成长线。逐项可编辑，确认后复用 `characterInput` 验证器和 `saveCharacter` 写入同名字段。“预览内容”对应补充备注；不再把整份人物设定降级塞入备注。缺失结构、未知字段、错误类型、超长、重复标签及空核心设定被拒绝，不静默回退。AI 不接收已有记录 ID 作为写入目标；人物关系和世界观关联继续在原资料编辑器中人工整理，不自动猜测 ID。

预览基线覆盖本小说元信息、所有章节的 ID/版本/顺序、人物与世界观 ID/版本、规划工作区版本、完整服务端模型目录及预算策略。模型名称、提供商、接口、密钥、超时、输出上限、报价或目录变化都会使旧预览无法保存；密钥和端点不发送给前端。生成前核对、生成完成、有效性检查及真正保存都校验基线。发现不匹配的预览永久标记失效，配置回退也不复活；生成期间变化不会签发可保存结果。

客户端每 2 秒以及窗口/可见性恢复时核对有效性；失效或暂时无法核对时禁用保存，保留全部编辑内容和导出。服务端保存时仍独立检查，轮询之间发生的变化也无法绕过。已经成功保存的同一预览/同一内容重试仅返回原收据，不再次写入；修改内容后重放被拒绝。相同生成请求并发提交在预留预算前拒绝第二份，取消、失败及超时会释放在途去重状态，已经预留的费用/token 不退款。

大库读取改进：版本摘要逐行哈希，不构建完整字段/正文数组；目录只查元信息；资料与规划引用按 ID 读取；新资料保存只回读新记录；规划完整读取预先按记录/角色归组章节链接；AI 弹窗只获取大纲归属摘要。引用目录提供搜索、翻页，每页最多 100 个 DOM 选项，跨页保留所选项。没有新增数据库迁移或依赖，没有调整原存储限额。

## 自动化范围与不可降低的断言

保留旧断言并增强人物字段断言。原“旧预览保存失败”浏览器用例现在同时验证主动失效禁用、直接提交仍返回 409、预览仍可导出和数据库保持完整，不以 UI 禁用代替服务端检查。

- 数据单元：结构化字段、必需结构拒绝、四类确认新增/幂等/原稿保留；小说、已有的人物、世界观、章节、规划修改及资料增删；模型、密钥、端点、报价、上限、超时和目录移除；配置回退后失效状态仍保持。
- 真实 HTTP API + Mock：取消传播、不退款、硬超时与重试、共享输入/token/费用预算、并发重复生成只调用一次 Provider、同时重复保存幂等、生成中/生成后模型变化、版本冲突。兼容 Provider 的 401/403/429/500/503 与非 JSON 响应通过注入 fetch 验证，禁止外部网络调用及敏感信息外泄。
- AI 规划 E2E：四类预览编辑新增、人物逐字段保存、取消/错误/冲突导出、浅/深/系统主题、窄屏，六类资料/模型变化使预览失效、超时、预算不足、保存响应丢失重试不重复新增、2,000 人物目录搜索/分页与 DOM 上限。
- Playwright Chromium、Firefox、WebKit 均安排新增专项、原写作回归及原完整套件；macOS Chrome 使用明确 Chrome channel，独立恢复浏览器也遵循相同引擎/channel。
- 继续 Linux lint、完整 typecheck、build 和完整单元/API；性能测试随 `npm test` 运行，JSON 指标上传为 CI artifact。原生 Mac Safari/iPhone 未运行，WebKit 自动化结果不等同于 Safari 人工验收。

## 性能方法、指标和实际失败

仅使用独立临时 SQLite：小型样本 100 人物 + 100 世界观 + 100 章节 + 400 规划 + 600 关联；大型样本 5,000 人物 + 5,000 世界观 + 5,000 章节 + 4,000 规划 + 14,000 关联。规划每类最多 1,000，遵循现有 2,000 项/类限制。大库每章含约 4,000 字符正文，人物/世界观含较长资料，大库 DB+WAL 实测约 214 MiB。夹具原有行在保存后逐项核对，只有明确确认的新记录增加。

版本基线/有效性各 30 个样本，空/选引用预览各 20 个，目录 5 个，旧完整内容哈希 3 个；报告 p50/p95/max、创建耗时、DB+WAL 字节、三类新增保存耗时及优化路径 RSS 增量。暖缓存单进程测量，RSS 为测试阶段结束相对开始的增量，不是独立峰值内存或长期泄漏结论；不包含真实模型网络耗时。

固定预算：版本基线和有效性 p95 <250 ms，预览 p95 <500 ms，单次确认新增 <3,000 ms，优化路径 RSS 增量 <128 MiB。另有确定性复杂度断言：无引用预览及目录不得调用整库资料/规划读取。所有预算保持初设值，没有为了通过测试放宽。

最初 RSS 增量 178 MiB、随后 152 MiB，均触发原 128 MiB 断言。对应日志保留为 `work/ai-planning-performance-first-failure.log` 和 `work/ai-planning-performance-second-failure.log`。发现单条规划引用仍读完整规划，以及版本摘要仍生成大数组，分别修为按 ID 读取和流式摘要后通过。

本地最近一次完整测试尝试中的性能用例通过，AMD EPYC 9V74 / Linux / Node 24.19.0，大样本观测：

| 指标 | 本地结果 |
| --- | --- |
| 版本基线 p95 | 107.68 ms |
| 带引用预览 p95 | 96.19 ms |
| 有效性核对 p95 | 88.93 ms |
| 确认新增世界观 / 人物 / 分卷 | 80.97 / 135.50 / 774.53 ms |
| 优化路径 RSS 增量 | 103.20 MiB |
| 同夹具旧完整哈希与新基线 p50 比值 | 约 108.7 倍 |

以上是本地开发观测，不冒充最终提交或其他硬件的保证。当前代码对应的最终 CI 测量、平台、样本和验收结果以 `ai-planning-performance.json` artifact 及 PR 报告为准。失败时也保存 last-measurement JSON。

## Firefox 写作回归的输入与清理修复

提交 `3f87727` 的 [PR CI 39417890459](https://github.com/shawnhhh/storyforge/actions/runs/39417890459) 中，Linux 的 lint/typecheck/build、157 项单元/API、Chromium 全套及 macOS Chrome/WebKit 全套通过，三个引擎的 AI 规划专项均 16/16。Firefox 写作回归为 40/41，后续完整 Firefox 套件因该失败未运行。

失败发生在原主动阅读滚动用例：单次合成 wheel(-1800) 在 Firefox 只移动约 296 px，未达到原 500 px 门槛；应用没有自定义 wheel 处理。现将同样 -1800 总输入拆成 6 次 -300 的滚轮动作，每次必须观察到实际上移，并附各次视口测量。原“至少离开光标 500 px”、保存前后视口/选区/焦点完全相等，以及继续输入后跟随光标 500 px 的断言全部保留。未通过调整产品滚动行为、阈值、跳过浏览器或删除测试来绕过失败。

失败清理时另有 route.continue 已处理错误：释放保存闸门后原 unroute 不等待在途处理；现用 Playwright unrouteAll({behavior:'wait'}) 等待已释放的真实请求处理完成，避免错误遮蔽主断言。两次原始 Firefox 失败日志保留在 `work/ai-v2/ci-118611268632.log` 与 `ci-118611239128.log`；本修复的最终验收仍以新提交 CI 为准。

## 剩余风险

- 原生 Safari/iPhone 输入法、触摸、下载和辅助功能焦点需要真实设备人工验收；自动化不能替代。
- 性能样本覆盖单个大作品；多位用户并行、多窗口长期压力、冷盘、低内存移动端及十万级资料未验证。版本摘要依然随本小说记录数线性增长。
- 人物关系与世界观关联不由模型自动建立，留给现有资料编辑器人工确认；不改变任何已有档案。
- 预览仍是 30 分钟/最多 100 项的临时状态，浏览器或服务重启前建议导出。已确认保存返回收据的幂等重试不会新增第二份。
- 不调用付费 AI，真实模型遵循结构的比例、产文质量、实际延迟和账单未验证；不合并 #19/#20，未来集成仍需复验共用模块。
