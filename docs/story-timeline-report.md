# 剧情大纲与故事时间线开发报告

日期：2026-10-16。分支：`feat/plot-outline-timeline-20261016`。基于最新 main `7633f65c1d0496974e0769bc65518168f480c565`，仅在独立分支开发，提交为 Draft PR，等待人工验收。

## 现有模型检查与最终实现

现有小说/章节是 `novels`、`chapters`；人物、地点、势力、历史事件复用 `characters`、`world_entries`；资料库已有 `character_world_links`、`knowledge_links` 和重要事件时间字段。规划已有总纲/分卷/章节大纲、剧情线、剧情卡片、伏笔、章节引用和版本化自动保存。

本轮没有再造上述实体。保留并回归总纲→分卷→章节大纲、卡片排序/编辑/搜索/状态/剧情线筛选；为大纲和卡片补充人物、地点、其他资料引用和原资料查阅。剧情卡片直接作为故事事件；统一时间线聚合卡片和已有资料库重要事件，展示名称、故事内时间、描述、参与人物、地点、章节，支持按时间序号排序和多条件筛选。编辑返回原记录，避免复制事件。

手机模拟发现进入规划前原写作页 `min-width:660px` 引起视觉视口偏移、按钮点击被导航/页头拦截。已在非专注窄屏工作区使用纵向布局、横向模块导航和章节列表，令作品→规划→写作的入口可触达。规划页采用单列、原生控件、44px 触控区域，并适配现有浅色/深色 Apple 风格。

## SQLite、迁移与恢复

- 基础版本保持 v4；已发布的 `0001`～`0004` 和 `planning_001.sql` 均未修改。
- 仅追加 `planning_002.sql`：两张人物/设定引用表、复合外键、目标索引、删除失效触发器。新模块依赖基础人物/设定表；正常启动仍是基础迁移在前。
- 规划迁移按连续具名历史执行，保留旧目标 v1 用于历史签名；未知/跳号/冲突表及降级拒绝，事务回滚保留原数据。
- 同小说校验同时在 API 与 SQLite 外键落实。删除人物/设定时只清理引用，保留事件、大纲和正文；规划版本递增，旧浏览器保存返回 409，保留并可导出草稿。
- 精确备份签名扩展至 14 种受支持结构：基础 v1 允许规划无/v1；v2、两类历史 v3、v4 允许规划无/v1/v2。保留 main 针对 dashboard-only/knowledge-only v3 冲突的精确识别与统一 v4 迁移。
- 新备份元数据使用 `planningVersion:2`，保留旧元数据支持；恢复只升级私有副本，新增表纳入原完整事务，恢复前安全快照包含新引用，失败全部回滚，原备份字节不变。

没有发现需要改写其他分支的关键数据库设计冲突。本轮既未占用新的数字迁移版本，也未修改其他功能分支。规划 v2 数据库和备份需要本版或更新程序，旧程序应拒绝未知模块结构。

## 并行分支兼容与潜在冲突

远端复查时 main 仍为 `7633f65`；可见的资料库、规划、工作台、AI、搜索偏好、编辑体验、备份恢复等现有 feature 分支均为 main 祖先。本轮直接使用整合后的 main，不移植旧分支的重复 v3 迁移。

当前可见远端没有独立的草稿保护或删除回收站分支，无法对其未提供的提交做三方合并验证。下列为具体集成风险和处理边界：

| 并行功能 | 可能冲突位置 | 集成约定/待验证 |
| --- | --- | --- |
| 草稿保护 | `PlanningPanel.tsx`、`Workspace.tsx`、规划草稿序列化与共享校验 | 保留已有 localStorage 键、版本、generation、串行保存和 composition 保护；新增可选引用数组必须保留，不能在草稿迁移/导出时剥离。重新加载前需允许导出冲突草稿。 |
| 删除回收站 | `PlanningPanel.remove`、`planning_002.sql` 删除触发器、`PlanningStore` 目标校验 | 本轮仅原有基础永久删除加明确确认，未实现回收站。后续软删除必须统一隐藏/挂起引用，并递增规划版本；恢复时决定是否恢复引用，不能由旧快照重新写回。代码已标记集成点。 |
| 回收站新迁移/备份 | `planning-migrate.ts`、`BackupService`、备份契约 | 如果并行分支也使用 `planning/002`，需协调新的未发布迁移名称并测试合并后精确签名；不得改写已经应用的迁移，也不得让恢复遗漏回收站或新引用表。 |
| 手机布局/编辑体验 | `workspace.css`、规划 CSS | 本轮修复了进入规划前的共享窄屏入口；后续布局分支需保留导航可达性、专注模式隔离，并回归手机往返写作/规划。 |

草稿保护不需改变基础数字迁移；若回收站将人物/地点改为软删除，本轮物理删除触发器不会代替其软删除生命周期，必须在正式集成时补齐对应失效机制。禁止直接把现有 `PlanningStore` 的整快照替换当作回收站删除日志。
