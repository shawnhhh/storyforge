# 剧情大纲与故事时间线

本轮从最新 main `7633f65` 创建 `feat/plot-outline-timeline-20261016`，复用现有「创作规划」和「创作资料库」，补齐跨模块引用和统一事件时间线。

## 使用

1. 小说 → 创作规划：沿用总纲、分卷、章节大纲及层级；剧情卡片沿用手动排序、搜索、剧情线/状态筛选、章节关联和四种状态。
2. 大纲和卡片可以勾选已有的人物、地点，以及势力、历史事件等其他资料。只引用资料 ID，不复制或改写资料。「查阅」在规划保存后打开原资料。
3. 「故事时间线」中每张剧情卡片就是一个事件：标题是事件名称，详细内容是事件描述（空时展示摘要），故事内部时间支持虚构纪年，时间序号决定先后。参与人物、地点、章节直接使用卡片关联。
4. 「新建事件」创建剧情卡片；「编辑剧情事件」回到原卡片修改时间、描述、状态与关联。时间线按序号升序，同序号保留卡片顺序，未填序号排在末尾；手动顺序与时间序号独立。
5. 资料库中原有「加入重要事件时间线」的设定也一并展示。人物沿用人物档案的设定关联，地点沿用事件指向地点的设定关联，章节沿用章节指向事件的资料引用。「打开资料库事件」编辑原资料，不生成重复事件。
6. 可按名称/描述/时间搜索，按来源、人物、地点、章节、状态组合筛选。状态筛选匹配有剧情状态的卡片。两类记录共用作者指定的时间序号尺度，不自动换算现实日期或合并同名事件。

沿用 Apple 风格浅色分栏、圆角卡片、原生控件和键盘焦点提示。390px 窄屏为单列，时间线控件和新增资料选择项提供至少 44px 触控高度。

## 草稿与删除

沿用原规划快照、700ms 串行自动保存、localStorage 草稿、中文输入法 composition 保护、409 冲突停写、导出和未保存导航拦截。旧草稿没有 `characterIds`/`worldIds` 时仍可读取；新引用随草稿恢复与导出。资料读取失败独立提示并可重试，不清除规划及已有引用。

关联目标被其他窗口删除时，SQLite 级联清理引用并提高规划版本；旧窗口保存返回 409，保留本机草稿。重新加载前可导出核对。其他窗口新增或重命名资料后，重新加载规划可刷新资料目录。

没有实现回收站。原规划删除增加明确的永久删除确认与先导出提示，沿用版本检查和事务；不会删除关联章节、人物或地点。后续集成点在 `PlanningPanel.remove` 和 `planning_002.sql`：软删除需要统一隐藏目标、清理/挂起引用并使规划版本失效；恢复规则交由公共回收站生命周期决定。

## SQLite 与备份

基础 `schema_migrations` 保持 main 的 v4，未修改任何已发布 SQL。新增具名迁移 `planning/002`，只增加 `planning_character_links`、`planning_world_links` 两张引用表、目标索引和删除失效触发器。复合外键保证规划与目标属于同一小说。规划快照在原事务中校验目标、写入引用并递增版本，不修改章节正文或资料内容。

正常启动先执行基础迁移，再依次执行规划迁移。新模块依赖已有的人物/设定表；`migratePlanning(db, 1)` 保留历史参考签名能力。拒绝跳号、未知历史、降级及冲突表，失败回滚，不重建用户库，也不占用其他功能的数字版本。

新备份使用 `planningVersion: 2`，校验完整连续模块历史和精确 schema。支持基础 v1 × 规划无/v1，以及基础 v2/v3/v4 × 规划无/v1/v2；保留 v3 的 dashboard-only、knowledge-only 两种历史精确签名。基础 v1 + 规划 v2 不受支持。仍检查所有结构对象、外键、引用语义和内容格式，不接受未知表。

恢复仅升级私有临时副本，先生成含全部当前模块的安全备份，再把新增引用表与所有业务表放入原恢复事务；失败一起回滚，原备份字节和校验和不变。旧程序不认识规划 v2，应拒绝打开/恢复新库，不能直接用旧二进制操作升级后的同一数据库。

JSON 小说导出、规划草稿导出包含新引用 ID；小说 JSON 的现有人物/资料库部分保留完整资料。Markdown/TXT 正文导出维持原行为，无新增 AI 调用。

## Mac Safari / Chrome 与 iPhone 验收

只使用专用测试目录，服务端不加载正式 `.env`：

```sh
STORYFORGE_DATA_DIR="$(mktemp -d /tmp/storyforge-timeline-data.XXXXXX)" \
STORYFORGE_BACKUP_DIR="$(mktemp -d /tmp/storyforge-timeline-backups.XXXXXX)" \
npx concurrently -k 'npm run dev' 'node --import tsx server/src/index.ts'
```

1. Safari/Chrome 创建虚构小说、章节、人物、地点和历史事件。建立总纲→分卷→章节大纲并关联资料，取消地点时其他资料和人物应保留，查阅应定位原资料。
2. 创建不同时间/状态的卡片，验证排序、筛选、刷新持久化、正文保持原样；检查时间线的同序号/无序号顺序及组合筛选。
3. 将资料库事件加入重要时间线，通过既有引用关联人物、地点和章节；确认统一时间线显示原事件，打开修改不会复制事件。
4. 中文输入法连续组词/选词，检查焦点、候选框、光标；断网编辑后刷新，重进原小说恢复并导出包含引用的草稿。
5. Safari 和 Chrome 同开规划，一端保存或删除测试人物后，另一端保存应冲突并保留草稿；未保存时查阅/切换小说受保护。
6. iPhone 竖屏编辑、关联资料、筛选、横竖屏切换，检查无水平溢出、触控、原生选择器、软键盘滚动。
7. 仅在测试目录手动备份、修改再两步确认恢复，检查大纲、卡片、引用、正文和资料库一起恢复，并保留安全备份。

自动化 Chromium 与手机模拟结果见开发报告；Safari/iPhone 真机仍需验收。当前云环境禁止 WebKit 下载域名（403 Domain forbidden），未计为通过。
