# 专注写作模式开发与测试报告

分支：`feat/focus-writing-mode`。基线：开发开始时最新 `main`，`7633f65c1d0496974e0769bc65518168f480c565`。未合并其他功能分支，未修改或推送 `main`，PR 保持 Draft。

## 界面与使用方式

- 点击“专注写作”或使用 `Control/⌘ + Alt/⌥ + Shift + F` 进入。默认隐藏小说库、章节侧栏、模块导航、章节跳转、格式工具和创作资料；保留退出、搜索、偏好设置、AI 辅助、保存状态与立即保存。
- “显示工具栏”可以按需恢复章节跳转、格式工具与创作资料，再次点击收起。退出后恢复原有侧栏、模块与工具栏；再次进入时默认收起工具。
- 保持同一个 Tiptap 实例和正文 DOM，进入／退出不产生正文写入。保留当前选区，退出时恢复进入前的正文滚动位置；切换章节后不会套用上一章的滚动位置。
- 正文居中，外层阅读宽度最大 850px，桌面左右留白 48px、行高为字号的 2 倍。沿用既有字体、字号及主题偏好，浅色使用柔和纸色、深色适配正文、引用、代码块、保存状态和目标弹层。窄屏专注界面适配到 390px。
- 专注模式下，AI 接受后的撤销提示留在工具行，不遮挡页脚的计时按钮，并适配深色文字与背景。
- 页脚沿用现有中英混排字数统计规则，并增加“本章字数 / 目标字数 · 百分比”。默认目标 2000 字，允许 1–1000000 的整数；进度最高显示 100%，实际字数继续增长。
- 点击章节进度可修改目标，按章节 ID 保存在当前浏览器的 `storyforge:writing-goal:v1:<chapterId>` 中。存储不可用时保留会话内目标并明确提示，不影响正文保存。
- 进入专注后开始计时，支持暂停、继续、重置。退出专注、页面隐藏、章节加载锁定时暂停；回到专注或页面重新可见时恢复，手动暂停保持暂停。计时按单调时钟累计，不以定时器触发次数计数。切章、刷新或重新加载编辑器后，本次章节计时归零。

| 操作 | 快捷键 |
| --- | --- |
| 保存 | **Control + Alt/⌥ + Shift + S，Mac 也使用 Control** |
| 进入／退出专注 | Control/⌘ + Alt/⌥ + Shift + F |
| 上一章／下一章 | Control/⌘ + Alt/⌥ + Shift + ↑／↓ |
| 退出专注 | Esc |

Safari 的 `⌘ + ⌥ + Shift + S` 原生“另存为”组合不再被应用保存拦截。常规浏览器保存、查找、打印、刷新、地址栏及标签页快捷键继续由浏览器处理。对话框、输入法组合输入、重复事件及已处理事件不触发工作区快捷键；macOS Option 改变字符时沿用物理按键代码识别。

## 修改边界与原功能

生产改动仅在 `src/features/novels/`：复用现有 Tiptap、统计插件和偏好设置，不新增编辑器内核。新增 `WritingProgress.tsx` 与 `focus-writing.css`；工作区只增加展示状态、工具展开和滚动恢复；编辑器增加展示参数与页脚组件。

没有修改 SQLite 表结构、迁移、API、共享正文契约、`autosave.ts` 或正文持久化路径。章节切换继续调用现有 `saveBeforeLeave()`；失败或冲突仍保留编辑器与草稿，重试、草稿导出、离页提示和显式重新加载可用。AI 继续使用既有预览、接受与自动保存流程，对话框 Esc 只关闭对话框。偏好仍由原有模块管理，不因专注模式另存一套设置。

测试隔离：`tests/e2e/run.ts` 为每轮启动独立临时数据库、备份目录和动态本地端口，进程退出后删除临时数据；不读取 `.env`。运行器移除全部 AI 提供商环境变量，浏览器 AI 生成由路由桩响应，单元／API 测试使用本地 Mock。没有访问真实小说数据库，也没有调用付费 AI API。

新增 10 项 E2E 验证：

1. 进入、展开工具、退出后，侧栏宽度、布局偏好、编辑器 DOM、选区和正文保持正确，展示切换不触发正文 PUT。
2. 实时字数与目标同步、超额封顶、章节目标互相隔离且刷新后保留。
3. 浏览器目标存储失败时，仍可编辑并自动保存。
4. 长文退出专注后恢复进入前滚动位置，不重建编辑器。
5. 专注模式切章等待待保存写入完成，再加载目标章节。
6. 版本冲突在进入／退出后仍可见，保留草稿、导出入口并阻止切章与覆盖。
7. 计时开始、手动暂停／继续、页面隐藏暂停、退出暂停、重新进入、重置和切章归零。
8. 保存失败保留当前章节和草稿，成功重试后才切章。
9. AI 桩预览不写正文，接受后自动保存；偏好主题／字号／布局生效，对话框 Esc 不退出专注。
10. 390px 专注界面无横向溢出，退出与计时可见；浏览器原生快捷键、Safari 另存为、IME 与 macOS 物理按键语义正确。

初轮 AI 测试发现桩数据缺少模型目录及结果 `usage` 字段，已按现有契约补全并增加 TypeScript `satisfies` 检查；未为此修改生产 AI 代码。默认沙箱禁止本地监听，最初出现 `listen EPERM`；最终测试在允许本地监听的执行权限内运行。

截图复核后，修复了专注模式 AI 撤销提示遮挡计时按钮及深色对比不足的问题。一轮全量测试期间仍有文件更新，trace 记录 Vite 热更新及页面重新连接，规划用例在重试保存时被页面重载干扰，该轮不计为全量通过。随后冻结文件，重新执行完整套件，最终 67/67 通过；没有跳过用例、扩大单例超时或启用自动重试。

WebKit 27.2（构建 2370）下载曾返回 `403 Domain forbidden`，包括 `playwright.download.prss.microsoft.com`。本轮检查 `/workspace/.cache/ms-playwright`、常用系统路径和临时目录，没有可用 WebKit 缓存或系统 WebKit，仅发现系统 Chromium；没有继续反复下载或改用非官方镜像。WebKit 的结果保持“环境阻塞”。

## macOS CI 与 Safari 验收

`.github/workflows/ci.yml` 增加 macOS 两个独立作业：真实 Google Chrome channel，以及 Playwright WebKit。覆盖新增专注模式、编辑器体验、自动保存滚动、AI 写作和搜索／偏好套件，保留截图和失败 trace。Linux 继续运行静态检查、构建、全部单元／API 和完整 Chromium E2E。

Playwright WebKit 不等同于已安装的 Safari 应用。合并前建议在实际 Mac Safari 和 Chrome 中使用**临时数据目录**完成以下人工验收：

- 开启、退出和展开工具，检查长篇滚动、选区及浅色／深色排版。
- 使用真实中文输入法确认组合期间不误触 Esc 或专注快捷键。
- 检查 Safari 原生另存为未被应用拦截，Control 组合能手动保存；检查章节切换与对话框 Esc。
- 切换系统主题与浏览器标签页，核对页面隐藏时计时暂停、重新可见时继续及布局恢复。单纯窗口失焦但页面仍可见时，计时继续。

本地复现（先安装对应浏览器；系统 Chromium 可通过 `E2E_CHROMIUM_PATH` 指定）：

```sh

npm run test:e2e -- --project=chromium

```

## 与草稿自动恢复分支的潜在冲突

检查远端分支列表及 `draft`／`recover` 名称搜索后，当前仓库没有可识别的独立草稿自动恢复分支，因此没有宣称完成实际合并验证。未合并或改写任何功能分支。

| 位置 | 可能的冲突及后续检查 |
| --- | --- |
| `Workspace.tsx` | 自动恢复可能修改章节载入、`session`、`dirty` 与切换流程；需同时保留恢复确认和现有 `saveBeforeLeave()`，不能因为切换专注绕过草稿保护。滚动快照必须限于同一正文节点。 |
| `ChapterEditor.tsx` | 自动恢复可能修改初始化、保存队列订阅或草稿提示。需保留 `focused` 参数、进度页脚与恢复入口，恢复正文后仍由既有编辑器事务更新统计；不要为切换专注改变组件 key。 |
| 样式与草稿提示 | 专注隐藏选择器仅覆盖导航、格式栏与创作资料，不覆盖 `.save-error` 或工作区错误。若恢复分支新增提示，需确认在专注模式仍可见、可操作。 |
| 浏览器存储 | 本功能仅存章节目标，不存正文草稿；恢复分支应保留独立存储键，避免清理草稿时误删目标或偏好。计时为当前编辑器会话状态，恢复重挂载时归零。 |
| 测试／CI | 两边如修改 Playwright 配置或 workflow，应保留临时数据隔离、AI 桩、两个浏览器项目和 macOS 作业。 |

## 剩余风险

- WebKit、本机 Safari、真实中文输入法尚无通过证据；macOS CI 必须检查实际作业结果。
- 章节目标仅在当前浏览器保存，不随作品备份或跨设备同步；计时不做跨刷新／跨章节历史统计。
- 未增加正文草稿自动恢复。强制关闭前未保存内容的边界仍由已有自动保存、草稿导出和离页提示决定。
- 长篇统计性能继续沿用现有插件，不承诺任意文档规模下的常量时间处理。
