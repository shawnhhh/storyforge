| 编辑入口 | 原机制与丢失风险 | 本轮处理 |

| 章节标题 / Tiptap 正文 | 700ms 防抖、串行队列、版本冲突及切章保护；失败草稿只在内存，刷新/退出丢失 | 每次编辑先写浏览器临时草稿，再进入原队列；AI 明确接受后的正文修改也沿同一入口保护 |

| 大纲、剧情线、卡片、伏笔 | 整个小说规划快照写 localStorage；同版本草稿会直接恢复并自动写回；单键可能被其他窗口覆盖 | 迁入统一 IndexedDB 草稿；旧键先安全转存再移除；任何遗留草稿均需明确选择，保留各窗口副本 |
| 小说创建 / 名称与简介设置 | 手动提交；关闭弹窗/刷新时未提交输入丢失 | 逐次输入保护；再次打开原入口提示恢复，仍须手动提交，不自动创建小说 |
| 资料关联 / 章节引用的目标、用途、备注 | 手动提交；失败时仅保留当前表单 | 按来源记录保护未提交表单；添加关联成功才确认清理，移除已有引用不误清新增表单 |
| 搜索、筛选、偏好、AI 配置/未接受的预览 | 搜索和筛选是临时界面状态；偏好已有 localStorage；AI 预览需明确接受才进入正文 | 保留原有行为，不把 AI 预览当正文写入；不新增任何 AI 请求 |

标签须点击“添加标签”、关系须点击“添加关系”后才成为档案内容；这些尚未添加的辅助输入、AI 要求和未接受的 AI 预览不属于本轮文档草稿快照，关闭前应自行复制。正文、已进入档案的内容及资料引用表单按上表保护。

## 使用与状态

- “已保存到数据库”：当前编辑器的内容已获后端确认；“临时草稿已保护 · 此浏览器”：已写入浏览器存储，不代表 SQLite 同步成功。后端保存失败、校验失败和版本冲突继续独立显示。
- 重新打开原小说和编辑入口后，先显示数据库内容，并检查本机草稿。检测到草稿时暂停编辑，提供草稿内容和基准/服务会话信息，以及“恢复此草稿”“保留数据库版本”“导出此草稿”。相同内容也允许人工核对，不静默处理。
- “恢复此草稿”是明确授权将这一份草稿作为当前编辑内容；正文/档案/规划随后沿原自动保存机制写回。小说设置和资料引用仍需点击原来的保存/添加按钮。恢复采用本次加载的数据库版本，若此后数据库再变化，原有 409 冲突机制继续阻止覆盖。
- “保留数据库版本”只丢弃对应的一份本机草稿。多个草稿可分别预览/导出/处理，不会批量清空其他章节或窗口。
- 正文与档案的“重新加载”保留本机草稿供再次选择。规划“重新加载”沿用原来的放弃确认，仅清理当前工作副本及其已选恢复来源，不删除其他窗口/小说草稿。

## 持久化与清理约束

浏览器数据库 `storyforge-protected-drafts` 的 v1 `drafts` store 与服务端 SQLite 无关。实体 key 包含类型、小说 ID、记录 ID；每次挂载的编辑器拥有独立 UUID，编辑修订拥有独立 token。新草稿不会覆盖其他窗口的草稿。同一编辑器使用递增修订序号比较新旧，不依赖系统时钟；暂未填完的数字字段也可从同步日志无损恢复。

输入事件内同步写 `storyforge:protected-draft:v1:*` 本地日志，并立即启动 IndexedDB 事务。同步日志填补刷新发生在 IndexedDB 事务提交之前的窗口；IndexedDB 支持更大的正文。若某一种存储不可用，另一种成功仍可保护；两者都失败则明确提示存储失败，不能宣称已保护。状态行保留高度，避免成功保存/保护状态切换移动写作视口。

数据库成功回执使用实际请求内容核对，只清理匹配内容的工作副本。IndexedDB 的读取/比较 token/删除在同一个读写事务内；同步日志按不可变 token 独立存储并删除精确键，避免跨窗口读取后删除的竞态。请求期间产生的新编辑、其他窗口更新后的 token 均不被旧回执删除。恢复来源保留到其工作副本成功保存，后续人工编辑再保存也安全清理来源。IndexedDB 暂不可用时以 token 墓碑阻止旧副本复现；无法完成清理时保留副本供下次核对。仅 IndexedDB 可用时正常清理其记录；暂时无法访问的日志镜像可能在权限恢复后重复提示，但不会自动覆盖数据库。

不增加服务端路由、SQLite 表、迁移或备份格式；不改变自动保存防抖、串行写入、409/404 和服务代际保护。唯一新增依赖 `fake-indexeddb` 仅用于开发测试。

## 数据边界与已知限制

临时草稿只在**同一浏览器配置、同一站点 origin（协议/域名/端口）**可见，不跨设备同步，也不进入 SQLite 备份。`localhost` 与 `127.0.0.1` 或不同端口之间不共享草稿。请固定日常访问地址。

Safari/移动浏览器可能在无痕会话结束、网站数据清理、空间不足或系统回收时删除浏览器数据；浏览器存储不能替代独立备份。同步日志写入失败而 IndexedDB 尚未提交时，极短的崩溃窗口仍可能存在；只有显示“临时草稿已保护”才表示至少一种存储已成功。大文档每次输入需序列化并尝试同步日志，超大作品应在目标 Mac 上验收输入延迟。

本轮没有全局草稿管理页。草稿随原记录入口被发现；已删除记录的孤立草稿保留在浏览器中，不会自动重建已删除内容。服务完全停止时页面可能无法加载数据库；重启服务、使用相同 origin 再进入原编辑器即可恢复。已打开页面仍能在后端不可用时保护输入。

WebKit 下载在本环境被网络策略拒绝（403 Domain forbidden），因此不把 Linux Chromium 的结果作为 Safari 实机通过证明。Mac Safari、iPhone/iPad 的原生输入法、强制退出、无痕存储策略仍需以下人工验收。

## 与“统一删除管理与回收站”的集成

1. 删除/软删除时先查询当前实体及子实体的草稿状态，提供导出、保留或明确放弃；不能把删除数据库记录等同于清空所有本机草稿，也不能让草稿恢复隐式取消软删除。
2. 回收站应复用稳定的小说/记录 ID，恢复后重新核对数据库内容、版本及服务会话。若重新生成 ID，须设计经用户确认的映射，禁止按标题匹配。
3. 规划草稿是小说级完整快照，包含条目及章节关联。恢复旧规划可能重新带回已删除条目；未来软删除服务应验证 tombstone/deletedAt 和引用目标，要求用户选择剔除或恢复，不能仅依赖前端旧快照。
4. 404、已软删除实体和已删除关联目标应继续停止自动保存，保留可导出草稿。彻底删除应单独确认本机草稿清理范围，按实体 key 和修订 token 清理，不使用全库 clear。
5. 备份恢复/数据库切换后不要自动重放草稿；保持服务代际拒绝旧窗口写入，在新页面展示人工选择。添加全局草稿入口时可以复用本轮存储与预览，但不要直接写回不存在的记录。
6. 预期文件冲突主要在 Workspace、StoryBiblePanel、PlanningPanel 和编辑器状态/删除入口；后端迁移与备份文件本轮无改动。合并两项功能时须回归“删除中仍有新输入”“回收后恢复旧草稿”“旧规划引用已删除章节”“另一窗口删除后保存冲突”。

## Safari / WebKit 兼容检查

草稿层使用 IndexedDB 事务、localStorage、Promise 和应用原有的 `crypto.randomUUID()`，不依赖 Web Locks、Chrome 专有文件接口或 IndexedDB `commit()`。Safari 的存储权限/配额错误有回退和明确状态，输入法仍沿用原保存队列的 composition 规则。现代 Safari 在安全上下文（本机 localhost 或可信 HTTPS）下支持这些接口；浏览器实现差异仍需实测。

已提供同一套隔离 E2E 的 WebKit 入口。在允许官方浏览器下载的测试环境可运行：

```sh
npx playwright install webkit
E2E_BROWSER=webkit npm run test:e2e -- draft-recovery.spec.ts
```

WebKit 模式不会传入 Chromium 的 executablePath，浏览器重启测试也会选择 WebKit。Playwright WebKit 不是 macOS Safari 实机的替代；本环境安装因官方 CDN 被策略拒绝而未执行 WebKit 浏览器用例，不能标为通过。

## Mac Safari 验收（仅隔离数据）

先把分支放入独立 checkout，执行 `npm ci`。不要复制真实 `.env`、data 或备份目录。Node 24 下以新的终端和临时目录启动：

```sh
TASK_DRAFT_DIR="$(mktemp -d /tmp/storyforge-safari-drafts.XXXXXX)"
SERVER_PORT=4311 STORYFORGE_DATA_DIR="$TASK_DRAFT_DIR/data" STORYFORGE_BACKUP_DIR="$TASK_DRAFT_DIR/backups" STORYFORGE_AI_API_KEY= STORYFORGE_OPENAI_API_KEY= STORYFORGE_DEEPSEEK_API_KEY= STORYFORGE_LOCAL_API_KEY= STORYFORGE_AI_MODELS_JSON= node --import tsx server/src/index.ts
```

另一个终端执行 `SERVER_PORT=4311 node node_modules/vite/bin/vite.js --mode test --host 127.0.0.1 --port 4312 --strictPort`。使用该隔离 checkout，没有本地 .env；两条命令不使用会读取 .env 的 dev:server/start:server 脚本。在 Safari 固定访问 `http://127.0.0.1:4312`，只创建虚构小说、两个章节、两个人物和设定；不要点击生成 AI。

1. 正常输入中文、emoji、粘贴及格式修改。观察临时保护与数据库状态；保存后刷新应只有数据库内容，没有遗留草稿提示。切换两章，确认标题/正文不串章；检查光标、选区、滚动及撤销/重做。
2. 停止**本次隔离后端终端**，保持前端运行。在正文（手机窄屏可使用现有“专注写作”）/人物/设定/规划输入独特虚构文本，等待“临时草稿已保护”和“保存失败”。刷新、关闭标签，再重开；服务停机时无法读取作品属预期。以同一目录和端口重新启动隔离后端，重新进入原入口，确认先询问版本且不自动覆盖。选择恢复，确认内容保存成功。
3. 重复步骤 2，看到保护后用 Safari 退出/强制退出；重新打开同一地址及编辑入口，分别验证恢复、保留数据库和导出 JSON。检查名称为空、规划标题未完成等暂时不能入库的输入仍可恢复。
4. 两个 Safari 窗口先打开同一章：停机后分别输入甲/乙，重启并再开第三窗口，确认两份都可预览/导出，处理一份不会清掉另一份。不同章节和不同小说重复验证。
5. 两窗口均加载同章后，甲成功保存；乙输入产生版本冲突。刷新乙，查看数据库内容和草稿，分别验证恢复和保留数据库。重复人物、世界观/资料库及规划；确认恢复仍经过后端版本校验。
6. 小说创建弹窗填写名称/简介后关闭再打开；资料关联填写用途/备注后刷新；确认恢复后不自动创建小说或关联，仍须点击原提交按钮。
7. 验证浅色、深色和窄窗口，提示不遮挡原操作。iPhone/iPad 若通过局域网访问，须另行配置可信 HTTPS 开发入口及前后端同源代理，遵守现有 Host/Origin 限制；不能为测试放宽应用安全检查。移动 Safari 重点检查输入法组合、应用切后台与标签回收后恢复。
8. 无痕模式/网站存储禁用时观察真实行为：若写入失败必须提示并可导出，不能显示虚假保护；结束无痕会话后不承诺恢复。验收后只关闭上述测试进程；清理时仅操作自己记录的临时目录。
