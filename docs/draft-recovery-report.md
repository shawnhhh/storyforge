# 草稿自动恢复与防丢失保护：开发与测试报告

## 开发成果

基线为 main `7633f65`，确认 PR #12 已合并且集成 head `c8e37a8` 是当前功能分支的祖先。独立分支 `feat/local-draft-recovery-20261016`，交付 Draft PR；不修改 main，不启用自动合并。

保存机制逐项审查、用户操作、恢复语义、数据边界、删除/回收站注意事项和 Mac Safari 步骤见 [完整说明](draft-recovery.md)。本轮增加共享的浏览器草稿存储、保护控制器、React hook 和恢复提示，接入章节、人物/世界观/资料库、规划、小说名称/简介、资料引用表单。

关键行为：用户输入事件立即保护，网络保存仍沿原队列；刷新/关闭后先展示数据库内容，发现本机草稿则要求选择，不自动重放；恢复来源直到成功写回才清理；请求期间的新修改、其他章节及窗口副本均按修订/token 隔离。修订序号避免时钟回拨误选旧内容；写入失败/存储限制明确提示。保留原 Apple 风格和模块布局，为状态保留高度，支持深色与窄屏提示。

本轮没有修改服务端、SQLite 数据结构、迁移、备份格式及 AI 请求链路。唯一增加的开发依赖是 `fake-indexeddb`；没有运行时依赖。

## 数据隔离

- 所有测试使用虚构小说及系统临时 SQLite / 备份目录，端口由运行器动态分配；浏览器重启测试使用额外的临时用户配置目录，完成后关闭测试浏览器并清理该目录。
- 不读取真实小说内容，不启动默认 data 服务，不修改/删除工作区既有数据库或备份，不连接用户 Mac。
- 后端由 `node --import tsx` 启动，不加载 `.env`；E2E 沿用已集成的 AI 环境清理，模型调用为 Mock。没有调用付费 AI API。
- 沙箱默认禁止本机监听；首次测试受 EPERM 限制。实际 HTTP/API 与 E2E 在获得环境的网络执行权限后运行，仍使用原运行器的隔离目录，并未复用用户服务。

## 开发中发现并修复的问题

1. 恢复后的 textarea 值会参与部分隐式标签定位。为小说简介和引用备注补上稳定、相同名称的 aria-label，新增流程验证通过。
2. 草稿提示出现/消失可能移动正文视口。固定状态行高度，并保留现有长篇滚动回归。
3. 统一存储后，原规划离线导出入口仍只读取旧 localStorage。已改为导出统一存储中的各份草稿，兼容旧键；禁止 localStorage 时不阻止仅 IndexedDB 的规划保护。
4. 首轮新增 E2E 的小说按钮精确名称未包含日期，以及 Playwright 对 `role=textbox` 的可编辑判断与 `contenteditable=false` 不一致。改用既有导航匹配方式、断言真实编辑属性和禁用状态，并验证选择前数据库无写入。
5. 完整备份回归发现恢复后的新页面会正确检测同浏览器旧窗口的未保存草稿。旧测试假设直接可编辑，已增加预览旧草稿、明确保留数据库版本、并核对旧窗口内容仍在的操作；不绕过恢复检查。
6. 小说弹窗本机草稿检查期间原 autofocus 无法聚焦被禁用的输入框。已在检查结束或版本选择完成时显式恢复名称焦点，保留取消/返回焦点行为；原有两项焦点测试通过。
7. 同步日志改为每个修订 token 的独立键；新单测在旧回执清理期间注入另一窗口的新输入，验证新内容不会被旧删除操作误删。
8. 移动端测试原先使用桌面侧栏与默认第一章假设；改为从现有移动作品卡片进入并显式选择测试章节，不改变产品导航。
9. 首轮存储失败单测没有等待错误事件。改为订阅实际保护状态，避免依赖固定微任务数。

## 已知限制与后续集成

浏览器草稿不跨浏览器/origin/设备同步，不进入 SQLite 备份；无痕结束、系统清理、存储满及突然断电不提供绝对恢复保证。大正文每次输入的序列化/同步日志开销需在目标 Mac 验收。服务完全停止导致首页无法加载时，须恢复服务后进入原入口。已删除实体的孤立草稿保留，不自动复活记录；全局孤立草稿管理页尚未提供。窄屏正文沿用现有专注模式；本轮未重排原来的多栏工作区。

标签/关系的尚未添加辅助输入、AI 写作要求与未接受的预览仍遵循原生命周期，不属于本轮实体草稿。AI 接受进入正文后即时保护。新增内容类型应通过同一保护接口接入，不应把服务端写入成功作为草稿创建条件。

与“统一删除管理与回收站”的主要交集是 Workspace、StoryBiblePanel、PlanningPanel 的删除/重载入口和小说级规划快照。后续要保留稳定 ID、验证软删除/引用目标、阻止旧草稿重建已删除实体；彻底清理需明确范围并按 token 删除，禁止全库 clear。具体六项约束见 [集成注意事项](draft-recovery.md#与统一删除管理与回收站的集成)。

Mac Safari 和移动 Safari 未作实机通过声明，WebKit 下载受阻已如实记录。已提供 `E2E_BROWSER=webkit` 的相同隔离用例入口，避免把 Chromium 路径传给 WebKit；这只表示测试入口可用，不代表 WebKit 运行通过。请按 [隔离验收步骤](draft-recovery.md#mac-safari-验收仅隔离数据) 验证原生中文输入、正常/强制退出、服务重启、多窗口冲突、恢复/保留/导出、深色及移动端后台回收，再决定正式评审与合并。
