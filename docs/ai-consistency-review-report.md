# AI 章节一致性审阅、写作布局和主题修复报告

分支：`feat/ai-consistency-review-20261019`。独立 Draft PR：[#20](https://github.com/shawnhhh/storyforge/pull/20)，目标 main。基线 `1a6895f` 是已合并的 PR #18；不引入 PR #19 的时间线、回收站或 PR #13/#15 原分支代码。

## 完成范围

- 只读一致性审阅：人物身份/性格/关系、世界观/规则、剧情逻辑/衔接。完整预览当前章节和明确勾选的本作品引用，勾选确认后才调用模型；指纹绑定实际 messages、引用版本、模型和参数。
- 依据检查：模型返回结构化问题、证据和建议；引文必须逐字存在于指定的已发送来源。缺失、伪造或不足两段不同原文的冲突降为不确定建议，所有语义判断仍需作者核实。
- 沿用模型目录、Provider、费用、token、请求和并发保护。取消、切章、正文变化及失效引用受到隔离；无 Key 不阻断其他写作功能。没有正文应用入口，没有结果持久化，没有数据库迁移。
- 留白修复：去除普通正文容器的居中最大宽度，统一标题与正文 24–32px 起点；标准/紧凑布局限制左对齐的行长，宽幅释放行长。专注模式保留 850px 居中容器并对齐标题，小屏避免 660px 强制画布。
- 主题修复：AI 对话框、模型、引用、结果、对比、控件、提示、边框和焦点共用全局语义变量，随浅色、深色、系统和跨标签页更新即时变化。

## 安全与人工验收

所有数据库由测试在临时目录创建，Mock Provider/transport 或浏览器拦截提供模型结果。没有访问真实小说数据库、备份或 `.env`，没有调用真实付费 AI。API Key 不写入前端、日志或数据库。正文保存队列、Tiptap 数据结构、专注状态、草稿保护和撤销机制未改动。

Mac Safari 人工验收（WebKit 自动化不能替代）：

1. 使用虚构测试作品，分别在 1440/1024/390px，切换标准、宽幅、紧凑布局，核对普通正文 24–32px 起点及标题对齐，进入/退出专注后居中阅读宽度合理。
2. 用中文输入法连续输入、选词、移动光标、撤销/重做和滚动；切换专注及 AI 弹窗后选区、滚动、正文不变，自动保存后刷新可恢复；沿用现有草稿恢复检查。
3. 打开 AI 写作和一致性审阅的模型、引用、预览与结果；切换浅色、深色、系统，改变 macOS 系统外观，确认所有表面和文字实时更新，键盘焦点清晰。
4. 只接本地 Mock AI，验证实际上下文预览与勾选确认。修改引用后重新确认；删除引用、取消、切章或正文变化后迟到响应不能污染当前章节。结果只读，预算不足友好报错，无 Key 时仍能正常写作。

详细操作和实现边界见 [功能说明](ai-consistency-review.md)。
