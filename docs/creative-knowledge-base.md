# 创作资料库

创作资料库基于已合并 main 的人物与世界观模块扩展，不依赖 PR #7。沿用本机 Express + SQLite、macOS 风格界面，以及既有资料自动保存、冲突保护和草稿导出。

## 整理和关联资料

1. 打开小说，进入「创作资料库」。可同时查阅人物、地点、势力组织、力量体系、历史事件及其他设定。
2. 选择「新增资料类型」，点击「新增资料」。人物与世界观详情直接复用原有编辑器，原「人物档案」「世界观」入口仍可使用，两处编辑同一份记录。
3. 通过左侧类型、角色分类、标签和搜索组合筛选。搜索覆盖姓名/名称、分类、标签、人物全部字段、设定内容与事件时间文本。无结果时可「清除筛选」。筛选不会丢弃详情中的未保存修改。
4. 人物档案继续管理有方向的关系、自定义关系类型及人物与设定关联；关联人物和设定可直接跳转查阅。未保存时先完成保存，再切换资料。
5. 地点、势力等设定的「资料关联与引用」支持设定间关联，填写目标资料、用途与备注并点击「添加关联」。目标会显示反向关联。人物—人物、人物—设定关联继续沿用原有机制，避免保存重复记录。

## 写作中的资料引用

在章节编辑器底部打开「查阅与引用创作资料」，选择当前小说的人物或设定，填写用途与备注后点击「添加引用」。可展开「查阅资料内容」，或点击名称打开完整档案；档案中的「被引用与反向关联」可以跳回引用章节。

引用是章节的创作参考记录，不向富文本正文插入特殊标记，不修改正文内容、字数、章节版本或小说聚合版本。修改资料名称/内容后，重新打开面板可查阅最新内容。引用用途最多 80 字符，备注最多 2000 字符，每部小说新增关联与引用合计最多 1000 条。

资料详情沿用 700ms 自动保存；新增关联/引用使用显式按钮保存，保存过程中禁止切换。网络失败时保留目标、用途和备注，可重试。版本冲突时不覆盖其他窗口的关联，先「刷新关联」，核对已保存记录后再添加。刷新关联保留当前待添加输入。表单输入在成功添加前不会持久化；切换资料或收起面板会放弃尚未添加的输入。

删除资料或章节会清除对应引用和关联，但不更改其他正文。删除资料前会要求确认；删除有引用的资料会使其他窗口的关联快照过期。不存在的或跨小说的目标均不能写入。

## 数据、迁移、备份和导出

- 新增 `0003_knowledge.sql`，仅创建 `knowledge_workspaces`、`knowledge_links`、索引和保护触发器；不修改 0001/0002，不重建人物或世界观表，不改写小说和章节记录。
- 基础结构版本升至 3，独立 planning 迁移保持原样。关联快照有独立版本，事务保存并拒绝旧版本；SQLite 外键及触发器保障作品范围与删除清理。
- 备份包含新增表；恢复时所有模块一同事务恢复，注入失败会回滚。旧 v1/v2 备份在私有临时副本中升级至 v3，原始历史文件保持不变，恢复前安全快照保留现有引用。
- JSON 小说导出增加 `knowledge.profiles` 和 `knowledge.references`，包含人物、世界观、已有关系及新增引用。Markdown/TXT 保持正文导出行为。
- 不引入账号、云存储或运行时依赖；本次开发不运行实际用户数据库迁移。

## 自动化验证与安全隔离

```sh
npm ci
npm run lint
npm run typecheck
npm run build
npm test
E2E_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

单元和 HTTP 测试创建系统临时目录或内存 SQLite；Mock HTTP 验证请求格式、编码及错误传播。浏览器运行器强制创建临时数据与备份目录、分配本机端口，服务端不加载 `.env`、显式覆盖数据目录、不复用现有服务，结束后关闭进程并清理。`knowledge.spec.ts` 覆盖混合资料 CRUD/筛选、原有关联跳转、章节引用往返、正文保留、JSON 导出、网络 Mock 失败、真实并发冲突及窄屏布局。旧模块的完整 E2E 仍需一起运行。

Mac Safari 人工验收：分别在宽窗和窄窗创建地点/势力/人物、输入中文及标签、建立关联并从章节查阅；确认所有保存状态恢复正常，重开页面后引用仍在，正文内容与光标行为正常。云环境 Chromium 测试不等同于真实 Mac Safari 验收。

本次自动化结果与隔离说明见 [验证报告](creative-knowledge-base-validation.md)。
