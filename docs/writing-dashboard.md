# 创作工作台

应用首页展示作品概览、总字数、已有正文的章节数、最近五个编辑章节、每日目标、连续写作天数与最近 14 天足迹。侧栏“创作工作台”可返回首页；当前草稿未保存、保存失败或版本冲突时禁止离开。继续写作直接打开最近编辑的章节；作品没有章节时进入原有的创建章节流程。

界面延用现有系统字体、按钮、小说弹窗与编辑器，新增圆角卡片和留白。深色模式跟随系统 `prefers-color-scheme`；首页在窄屏切换为单列卡片及顶部导航。进度条与输入框具有可访问名称，目标保存及失败提供状态反馈。

## 统计口径

- 总字数与编辑器使用同一份 `shared/domain/word-count.ts` 算法：汉字逐字、拉丁词及数字段各计一字；标点、空白、格式不计数。
- 当前数据没有“章节完成”状态，因此进度明确展示“已有正文 / 总章节”，不推断章节完成情况。
- 每日记录使用 **UTC 自然日**；每次成功保存只累计 `max(0, 新字数 - 原字数)`。标题、格式和等字数替换不增加字数；删减不扣除此前记录，删除后重新写入可能再次累计。
- 活动记录从此功能启用后开始，不依据旧章节更新时间回填历史。删除作品会减少当前总字数，但保留已发生的历史写作记录。
- 连续记录按每日新增字数大于零计算；今日未写时可延续至昨日，超过一天未写归零。最长连续记录统计所有已记录日期。
- 每日目标默认 2,000 字，可设为 1–1,000,000 的整数，保存在本机数据库中。目标已超额时进度显示 100%。

## 数据与兼容

复用 `NovelStore`、`/api/novels`、`/api/chapters/:id`、通用 API 客户端及服务代际/来源保护。新增：

- `GET /api/dashboard`：同一个 SQLite 只读事务内聚合作品、章节、当前总量、写作历史与目标，不向浏览器返回正文。
- `PUT /api/dashboard/goal`：校验并更新每日目标。
- schema v3 仅新增 `writing_days` 和 `writing_settings`，不修改已有小说或正文。章节保存与写作记录处于同一事务，版本冲突、失败、回滚不会产生记录。

备份包含两个新表；恢复原子替换所有表，并保留恢复前安全快照。v1/v2 备份先在私有副本迁移至 v3，原备份字节不变；旧备份的目标为默认值、写作历史为空。本分支从 main 开发，不依赖 PR #7。

## 隔离验证

`npm test` 使用内存数据库或 `mkdtemp` 创建的专用目录；`npm run test:e2e` 会启动独立 API/Vite 服务，强制覆盖数据和备份路径，不加载 `.env`，结束后移除临时数据库。禁止直接启动使用真实 `data/` 的服务进行测试。

```sh
npm run lint
npm run typecheck
npm run build
npm test
# 已安装 Playwright Chromium 时无需指定路径
E2E_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

新增单元/API 测试覆盖嵌套富文本统计、增量保存、失败回滚、UTC 连续记录、v2 升级、目标校验、重启持久化和备份恢复。新增浏览器测试覆盖工作台入口、真实保存后的统计、精确章节续写、目标持久化、失败恢复、草稿保护，以及桌面/手机的深浅色布局。
