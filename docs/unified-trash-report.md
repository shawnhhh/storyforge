全局入口位于侧栏“回收站”。列表显示对象名、类型、删除时间、保留截止时间和各类影响数量；可查看归档正文/资料、恢复、经“···”菜单永久删除。所有永久删除均要求再次输入完整名称。支持键盘焦点、Esc 取消及手机布局，沿用系统字体、浅色边框和原生确认框。

人物关系、引用和规划是快照保存：同一次保存移除的关联会合并为一个回收站项；规划恢复还可能还原同次结构变更。取消确认不发起删除；尚未保存的表单修改继续沿用现有自动保存与草稿保护。

## 数据安全与关联策略

### 默认业务软删除

采用“事务内归档后从活动集合移除”的软删除方式，而非给每张业务表添加过滤标记：在 `BEGIN IMMEDIATE` 中读取删除前快照，执行原有活动表删除/快照保存，识别被移除的记录和关联，将其写入 `trash_entries.payload` 后提交。任何归档失败会回滚整个事务，活动数据与关联仍然存在。

这保留了原有活动表、外键和查询语义。活动表上的 SQLite `DELETE` 不等于用户永久删除：被删除行和全部受影响外键关联仍由同一事务存入回收站。仅回收站永久删除/到期清理才移除归档记录。

只截取与操作相关的表：人物自动保存不会扫描章节正文；章节删除仅保存该章正文及受影响关联。整本小说删除需读取本小说完整快照；大库峰值内存和事务时长仍需在 Mac 以虚构大库压测。

### 恢复和永久删除

- 先恢复所属小说；单独删除的子项目保持独立，不因恢复小说而自动复活。
- 恢复按父对象优先顺序插入，SQLite 复合外键、章节跨小说触发器和最终 `foreign_key_check` 共同校验。引用目标缺失、对象主键已存在、非法正文/记录格式均阻止恢复。
- 规划的关联变更保存 before/after 快照。恢复前必须与 after 数据一致；相关规划后续被编辑或删除时，拒绝覆盖，整笔回滚，提示先处理关联冲突。没有“强制覆盖”按钮。
- 恢复后递增小说、章节、人物、设定及规划/资料工作区版本，阻止旧窗口或旧草稿自动保存静默覆盖恢复结果；不会把恢复字数再次计入每日写作增量。
- 永久删除只移除一个归档记录，不改活动内容。若其他回收站项目仍依赖该项目内的小说、人物、世界设定、章节或规划对象，阻止永久删除并提示先处理依赖项目。
- 列表/预览为只读，`Cache-Control: no-store`；预览作为文本渲染，不执行归档中的 HTML。

### 后端校验与本地权限边界

所有 HTTP 删除必须携带 `confirmed: true`，整本小说删除额外校验 `name` 完全相等，并检查并发版本；恢复与永久删除检查归档当前存在状态、确认参数，永久删除再次检查名称。关联快照 PUT 同样在后端识别移除对象/引用并要求确认。

复用现有单机权限模型：只监听 `127.0.0.1`，检查 Host、浏览器 Origin、JSON 类型；备份忙时返回 423，旧服务/备份恢复 generation 返回 409。没有新建多用户账号权限体系，不支持部署到公网后直接作为多用户服务使用。数据库 store 是受信任的服务内部接口，面向浏览器的校验在统一 API 路由执行。

### 30 天清理

每条归档保留 `deleted_at` 与恰好 30×24 小时后的 `expires_at`，使用 UTC ISO 时间。恢复在截止时刻及之后由服务端拒绝，前端按钮状态仅作提示。

本地服务启动时（自动备份启动前）清理一次，之后每小时检查。任务复用同一 SQLite 连接并避开备份/恢复 busy 状态，服务锁排除第二个应用进程。筛选、保留元数据检查、依赖判断和批量删除处于一个写事务中；异常整批回滚并记日志，下次启动/小时重试。元数据不符合精确 30 天、正文损坏或关联无法安全移除时保留数据，不猜测期限。

服务关闭或 Mac 休眠期间不清理；重新启动后补做。仍被其他归档引用的记录可能超过 30 天保留，直到依赖已处理；依赖环保守保留，禁止误清理。系统时间严重跳快会影响所有基于本机时间的保留策略，当前没有外部可信时钟。

回收站保留期限与备份保留策略相互独立。永久删除或到期清理不会偷偷删除已有备份；备份中的历史创作内容仍可能存在。

## 数据库迁移、备份与兼容性

- 新增 `0005_trash.sql`，基础 schema 从 v4 升至 v5，仅创建 `trash_entries` 与期限/小说索引，不修改既有业务表、正文或排序字段。
- 迁移仍在单个事务中登记版本；重复运行幂等，遇到同名冲突表回滚并停止启动。历史两种 v3 结构精确识别逻辑仍保留，仅在 v3 模块签名计算时排除新增 v5 脚本。
- 备份完整签名扩展为 v1、v2、工作台 v3、资料库 v3、v4、v5 × 无 planning / planning v1，共 12 种。旧备份仅迁移私有副本；不重写原文件/校验和。
- v5 备份校验包括归档 payload 的表/列白名单、人物/设定字段与富文本格式。恢复前创建安全备份，活动数据、归档、各模块与迁移表在同一事务恢复；故障注入验证全部回滚。
- 恢复旧备份会恢复该时间点的完整数据集合，回收站初始化为空；恢复前安全备份保留当前回收站。恢复 v5 备份会一起恢复回收站时间戳，不重置 30 天时钟。
- 搜索、导出、写作工作台、人物及规划继续只读活动表，不会显示已删除对象。恢复后使用原 ID；章节顺序、正文、关联回归后恢复可检索。每日写作历史不因删除或恢复而加减，当前总字数只统计活动章节。
- 升级后不要用旧版代码打开 v5 库；需要回退时保留升级后的文件，用合适版本在独立目录恢复受支持备份，禁止手动删除迁移记录或覆盖 SQLite/WAL。

## Mac 本地隔离验收

1. 在已有工作目录先保存未提交改动。同步本功能分支，保持 main 不动：`git fetch origin`，`git switch feat/unified-trash-20261016`；确认 Node 24，运行 `npm ci`。
2. 终端 A 仅启动临时数据库/备份服务，不加载 `.env`：

   ```sh
   task_data_root="$(mktemp -d "${TMPDIR:-/tmp}/storyforge-trash-acceptance.XXXXXX")"
   SERVER_PORT=3001 STORYFORGE_DATA_DIR="$task_data_root/data" STORYFORGE_BACKUP_DIR="$task_data_root/backups" STORYFORGE_AI_API_KEY='' node --import tsx server/src/index.ts
   ```

3. 终端 B 在同一源码目录运行 `npm run dev`。Safari/Chrome 打开 `http://127.0.0.1:5173`。全部创建虚构小说、两章正文、两位人物与关系、地点/势力、章节资料引用和大纲层级；等待状态“已保存”。不要点击真实 AI 服务。
4. 取消章节删除，确认正文仍在；确认删除后在回收站查看正文与截止时间，取消一次恢复，再确认恢复，检查排序、检索和引用。
5. 测试整本小说删除：空输入、错字和末尾空格不能确认；取消保留作品；完全匹配后进入回收站，恢复后核对各模块。单独删除章节后再删小说，子项先恢复应被阻止；父小说永久删除也应被阻止，先恢复父小说再恢复子项。
6. 删除有关系/引用的人物、地点及规划，在回收站恢复；另一窗口修改关联规划后恢复应提示冲突，原数据与回收站项均保留。永久删除先取消、再输入准确名称确认，检查该条消失且活动内容不变。
7. 只在该临时服务中创建备份：归档一个对象 → 手动备份 → 恢复对象 → 恢复刚才备份（按既有整库确认流程）→ 整页刷新 → 核对回收站重新出现并可恢复。不要选择真实备份目录。
