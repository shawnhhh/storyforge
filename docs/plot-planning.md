# 第五阶段：大纲与剧情规划

在作品工作台点击「创作规划」。大纲、剧情线、卡片、伏笔按作品隔离，正文仍由原编辑器负责。当前分支从 main `2c82eff` 创建；开发期间 PR #3 合并后，已更新到 main `1038ce3` 并整合第三阶段。现已整合 main `191ebb0` 中已合并的 PR #4。

## 功能与操作

- 小说大纲：总纲、分卷、章节大纲；通过「上级大纲」调整树形层级，↑/↓ 调整同级顺序。删除父节点时子项提升一级。大纲类型与层级独立，最多 64 层。
- 剧情线：主线、支线、自定义线，支持标题、内容、排序和删除。删除剧情线后卡片保留并改为未分配。
- 剧情卡片：标题、摘要、详细内容、状态、所属剧情线、多个关联章节；搜索、剧情线/状态筛选、列表/卡片视图、手动排序。故事内部时间由自由文本和可选整数序号组成；勾选时间排序时按序号升序，未填序号排在末尾，同序号保持原顺序。筛选或时间视图下暂停手动调序，避免顺序含义不清。
- 伏笔：未埋设、已埋设、推进中、已回收；分别记录多个埋设、计划回收、实际回收章节，以及其他章节与多个剧情卡片。提供搜索、状态/未回收筛选、数量统计和已安排但尚未回收的提醒。已回收却缺少实际回收章节时提示补全。提醒不会推断作者当前写作进度或自动改变状态。
- 删除卡片时解除伏笔引用，保留伏笔本身；删除章节由外键解除关联，保留规划记录，并使旧规划版本失效。任何规划操作都不会改写章节标题或正文。

## 保存、草稿与冲突

所有规划作为一个作品内的版本化快照保存，服务端事务内检查版本、作品归属、树形循环、关联目标及状态。成功后规划版本与小说聚合版本递增；章节版本与正文不变。返回写作时刷新小说元信息。

每次输入先把草稿写入浏览器 IndexedDB 与同步本地日志，再进行 700ms 防抖、串行 HTTP 保存。规划请求超时 12 秒。中文 composition 期间只保留草稿、不发起新写入；已有请求返回也不会替换正在输入的文字。必填标题暂时清空时仍保留草稿，补全后可继续保存。每类最多 2000 项，整体遵循现有 API 1MB 请求上限。

网络失败不清空草稿、不自动连续重试，允许「重试保存规划」；404/409 停止重试，允许继续编辑、导出草稿并确认重新加载。检测到任何旧草稿均先询问恢复或保留数据库版本，选择前暂停编辑和自动写回，避免恢复数据库或重启服务后覆盖数据。不同作品的草稿使用不同键。存储不可用或空间不足时明确提示，并保留当前页面内容以便导出。

未保存时阻止切换作品、返回写作和其他公共写操作；关闭/刷新页面请求确认。刷新后重新进入原作品的创作规划会提供版本选择，明确选择恢复后才进入自动保存。旧版 localStorage 草稿先安全转存，不会静默丢弃。详见 [草稿保护说明](draft-recovery.md)。若服务仍离线，在作品及规划入口已可访问的情况下，规划加载错误页可「导出本机规划草稿」；首页完全无法读取小说时须等待服务恢复。浏览器隐私模式、清理站点数据或更换访问端口可能使本机草稿不可用；服务端已保存数据不受影响。草稿不会进入数据库备份，保存后才成为正式数据。

## 数据库、备份与导出

基础 `schema_migrations` 及 main 的 `migrate.ts` 保持原样，沿用第三阶段的基础 v2，不新增冲突的数字版本。`openDatabase` 在基础迁移完成后运行 `migratePlanning`，后者使用独立 `planning_migrations` 表登记 `planning/001`，SQL 为 `planning_001.sql`。模块迁移在自己的 `BEGIN IMMEDIATE` 中运行，失败整段回滚并停止启动；重复启动不重建表，不覆盖冲突表，不修改已存在的基础数据。

表结构：`planning_workspaces` 保存作品版本；`planning_records` 保存分类型、有序的记录及 JSON 扩展字段；`planning_chapter_links` 保存多章节、多角色引用。外键和触发器保证章节存在、作品归属、删除清理和版本失效。人物等跨模块引用尚未实现，可后续增加独立关联表，不复制人物/世界观实现。

新备份使用基础 `schemaVersion: 2`，另记 `planningVersion: 1`；严格接受基础 v1/v2 × 无 planning/planning v1 的四种完整 schema 签名，并检查人物、世界观、规划语义与章节归属。恢复旧快照时只升级私有临时副本到基础 v2 + planning v1，然后在一个事务里恢复正文、人物、世界观和全部规划表；原始备份保持字节不变。恢复前安全备份包含全部当前模块，注入恢复失败时一起回滚。未运行任何真实用户库的迁移或恢复。

JSON 小说导出增加可选 `planning` 字段，保留原格式与正文；Markdown/TXT 继续输出小说正文。规划界面的「导出规划草稿」可单独保存完整规划 JSON。目前没有导入/自动合并规划 JSON 的入口。

## PR #3 的兼容性

- 已整合 `BackupService` 的四种参考签名、模块校验及完整恢复表清单。私有恢复副本先升级基础版本，再运行规划迁移，人物四张业务表与规划三张业务表在同一恢复事务内处理。
- 自动化测试验证四种旧快照组合、第三阶段人物关系/世界观关联保留、规划章节关联保留、安全备份、失败回滚及原备份字节不变。
- 复用第三阶段提取后的通用 HTTP 客户端与服务会话 token；导航沿用现有模块按钮，规划作为独立视图加入。

## 验证方式与 Mac Safari 实机验收

所有自动化测试使用 `mkdtemp` 的 SQLite 及备份目录，E2E 不复用已有服务或 `.env`。单例浏览器用例上限 45 秒，断言 7 秒，整套上限 240 秒，不配置失败自动重跑。

使用专用验收目录启动，不对正式作品执行删除或恢复：

```sh
STORYFORGE_DATA_DIR="$(mktemp -d /tmp/storyforge-phase5-data.XXXXXX)" \
STORYFORGE_BACKUP_DIR="$(mktemp -d /tmp/storyforge-phase5-backups.XXXXXX)" npm run dev:all
```

1. Safari 打开终端给出的 `http://127.0.0.1:5173`，创建甲、乙两部测试小说，甲创建至少三章并输入可识别正文，等待已保存。
2. 甲进入创作规划，建立总纲→分卷→章节大纲，设置多个章节关联，调整上级及同级顺序；刷新后重进甲，核对标题、内容、顺序与关联。删除父大纲，核对子项提升一级；返回写作检查正文完全一致。
3. 用 macOS 拼音在详细内容中连续组词、选词，观察焦点、候选框和光标不被保存打断；等待已保存。清空必填标题并刷新，重进规划，确认未命名草稿和内容仍在，补全后保存。
4. 建主线、支线、自定义线与多张卡片；测试摘要搜索、剧情线/状态筛选、列表/卡片视图、手动排序；输入非现实日历时间标签与序号，确认内部时间升序及空序号在末尾。
5. 建伏笔，关联两个卡片、多个章节及三类回收角色；依次切换四种状态，检查未回收筛选、统计、提醒、已回收缺少实际章节时的提示。
6. Safari 响应式设计模式或缩窄窗口至约 390px，确认规划页面无水平溢出，能选择作品、编辑、筛选。切到乙应看不到甲的规划，切回甲后数据仍在。
7. Safari 编辑规划时停止后端（或开发菜单启用离线），确认保存失败且文字保留，可导出规划草稿；刷新并重启后端，重新选择原作品，确认恢复草稿并能重试保存。另验证断网加载页能导出本机草稿。
8. Safari 和 Chrome 先打开同一作品的规划，Safari 保存后 Chrome 再编辑，应出现版本冲突、保留草稿且不覆盖；导出 Chrome 草稿，确认重新加载后读取 Safari 的版本。
9. 甲规划已保存后手动备份，再改规划和测试正文；仅在专用验收目录执行两步恢复，核对所有规划和正文共同恢复、安全备份可见。恢复后旧窗口不能自动覆盖；页面刷新后核对数据。
10. 全部保存后重启服务，再检查作品、规划、关联及正文。Mac Safari 实机验收需人工完成；Linux Chromium 自动化不替代该步骤。
