# 人物档案与世界观工作台

打开一本小说，在工作台顶部选择“人物档案”或“世界观”。所有资料仍通过本机 Express API 保存在 SQLite，按小说隔离，无账户或同步。人物与设定的修改不改动章节正文，也不增加小说或章节的版本。

人物支持姓名、别名、性别、年龄、身份、外貌、性格、背景经历、人物目标、角色成长线和备注。角色分类可输入主角、配角、反派或自定义文本；标签逐项添加，可随时移除。搜索覆盖名称、分类、标签和全部资料内容，标签与分类筛选同时生效。

人物关系按“当前人物 → 目标人物”保存，可使用亲属、朋友、敌对、师徒或自定义关系。反向关系由另一份人物档案管理，详情也显示其他人物指向此人的关系。人物可以关联同一本小说的地点、组织和其他设定；设定详情显示关联人物。删除人物或设定前会要求确认，关联随目标删除而移除。

世界观包含地点、势力组织、力量体系、历史事件、其他设定。每项均可选择加入重要事件时间线；历史事件的新资料默认加入。时间文本可自由填写，例如“新纪元三年·冬”；时间线按整数顺序升序排列，同序号按创建时间和 ID 排列，不尝试解析虚构历法。

## 保存与草稿保护

- 新增操作先在本机创建“新人物”或“新设定”，然后直接编辑。请等操作完成后再次点击新增，避免因响应丢失重复创建。
- 表单停止输入约 700ms 后自动保存，也可点击“立即保存”或按 ⌘S / Ctrl+S。中文输入法组合输入期间暂停保存。
- 同一份表单只有一个写请求在途，后续修改按服务器返回的版本串行保存。显示“已保存”才表示最新修改已收到服务器确认。
- 等待保存、保存中、保存失败或冲突时，切换小说、模块、选中资料及删除操作会被禁用；刷新或关闭页面时浏览器会提醒未保存修改。浏览器对关闭提示的显示规则可能因用户交互和平台不同而变化。
- 网络失败会保留表单，可点击“重试保存”。另一个窗口修改或删除资料、服务重启或备份恢复导致的 404/409 会停止自动重试，防止覆盖新版本。
- 冲突时可继续编辑并“导出资料草稿”。导出 JSON 后可重新加载资料；重新加载会明确确认放弃当前修改。服务重启或备份恢复后，需要刷新整个页面以取得新的会话代号。草稿下载用于保留内容，当前没有资料 JSON 导入入口。
- 未保存草稿只在当前页面内存中保留，不使用浏览器本地存储；强制关闭页面仍可能丢失尚未确认保存的修改。

## Mac Safari 手动验收

在独立测试数据目录启动服务（同时指定项目外独立备份目录），不要以真实作品数据库执行删除验收。使用 Node 24，按 README 安装并启动。

1. Safari 打开 `http://127.0.0.1:5173`，新建小说和章节，输入中文、换行、emoji、`<&>`，等待正文“已保存”。
2. 打开“世界观”，新增地点及历史事件，填写长文本、自定义标签、虚构时间和不同顺序；检查分类、搜索、标签筛选和时间线排序。
3. 打开“人物档案”，新增两个人物，填写全部字段、自定义角色分类与标签；使用中文输入法编辑，确认组合输入结束后保存。添加师徒关系，勾选地点关联，等待“已保存”。
4. 刷新页面，重新选择小说与模块，核对人物字段、标签、关系、设定和关联完整恢复。返回章节写作，核对原正文、格式和自动保存仍正常。
5. 在 Safari 第二个窗口打开同一人物；第一窗口修改并保存后，第二窗口编辑。第二窗口应显示冲突，保留草稿并阻止切换；测试草稿下载、取消重新加载、确认重新加载。
6. 停止本机后端后编辑设定，确认保存失败且内容保留；重启后先导出草稿并刷新页面（服务重启会更换会话代号），确认没有旧窗口静默覆盖。可用开发工具临时中断 PUT 请求测试无需重启的“重试保存”。
7. 新建另一部小说，确认人物和世界观为空。回到原小说，删除关系、人物及关联地点，检查确认提示、列表及关联更新，正文保持不变。
8. 分别用约 1440px、1024px、700px 和 390px 宽度检查可滚动列表、表单、按钮和键盘焦点；窄屏资料列表位于详情上方。确认长标签和长名称不会撑出视口。

## 自动验证范围

`server/tests/profile-autosave.test.ts` 测试前端保存队列的串行写入、版本更新、404/409、网络失败重试、非法输入、中文组合输入及卸载行为，并测试中文搜索、标签组合筛选和时间线排序。该文件不打开数据库。

`tests/e2e/story-bible.spec.ts` 使用现有隔离测试运行器，覆盖人物/设定 CRUD、字段与特殊字符、搜索筛选、关系与关联、刷新恢复、小说隔离、时间线、冲突草稿下载、删除冲突、网络失败和窄屏布局。运行器使用系统临时数据库与备份目录，不读取真实用户数据。Chromium 自动化不能替代 Mac Safari 实机验收。
